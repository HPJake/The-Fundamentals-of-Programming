## 一、题目是什么？

在 **8 × 8** 的棋盘上放置 8 个皇后，使任意两个皇后都不处在同一**行、列或斜线**上。

- **输入**：无。
- **输出**：输出全部合法方案。每个方案先输出编号，再按 8 行打印棋盘：皇后用 `*`、空格用 `.` 表示，同一行的两个字符之间有一个空格。
- **排序**：按照第 1 列、第 2 列、……第 8 列皇后所在的行号，按**字典序从小到大**输出。
- **正确方案数量**：共 **92** 种。

### 第一种合法方案

把“第 `col` 列的皇后位于第几行”写成序列：

```text
pos[1..8] = [1, 5, 8, 6, 3, 7, 2, 4]
```

对应棋盘：

```text
    第1 2 3 4 5 6 7 8列
第1行  * . . . . . . .
第2行  . . . . . . * .
第3行  . . . . * . . .
第4行  . . . . . . . *
第5行  . * . . . . . .
第6行  . . . * . . . .
第7行  . . . . . * . .
第8行  . . * . . . . .
```

> 上面的行列标题用于解释；真正提交时不输出这些标题。

## 二、为什么用 DFS（深度优先搜索）？

最直接的想法是：第一列放一个皇后，再去第二列放一个，直到第八列。如果当前列某个位置会攻击已经放置的皇后，就跳过它。

**关键优化：按列放置，每列只放一个皇后。** 于是“同一列冲突”被天然避免，搜索时只需检查：

1. 当前**行**是否已被占用；
2. 当前 `\` 方向斜线是否已被占用；
3. 当前 `/` 方向斜线是否已被占用。

这一题不属于“选或不选型 DFS”：一层对应**一个列**，在这一层枚举所有可能的**行**，属于“枚举下一选择型 DFS”。

### DFS 参数

```cpp
void queen(int col)
```

- `col`：现在准备为**第几列**安排皇后；
- `queen(1)`：第一列还未放置，从第一列开始；
- `queen(3)`：第一列、第二列已经放好，轮到第三列；
- `col == 9`：前 8 列都放好了，发现一个完整方案。

### 搜索树示意（前两层）

```text
queen(1)：给第1列选择行
│
├── 选第1行（如果合法）→ queen(2)
│    ├── 尝试第1行 → 冲突，跳过
│    ├── 尝试第2行 → 可能有斜线冲突，跳过
│    ├── 尝试第3行 → 若合法，进入 queen(3)
│    └── ……第2列的所有合法行都尝试完，返回
│
├── 撤销第1列第1行的选择，再选第2行 → queen(2)
├── ……
└── 选第8行（如果合法）→ queen(2)
```

> 这是一棵**搜索树**；每条搜索到 `queen(9)` 的路径，对应一个满足全部条件的八皇后方案。

## 三、只用一维数组记录棋盘

不需要保存整个二维棋盘。定义：

```cpp
int pos[9] = {};
```

含义：**`pos[col] = row`**，表示“第 `col` 列的皇后放在第 `row` 行”。例如：

```cpp
pos[3] = 5; // 第3列的皇后在第5行
```

因为行号、列号都习惯从 **1** 开始，所以开长度为 9 的数组，合法使用 `pos[1]` 到 `pos[8]`。

输出棋盘时，遍历每个格子 `(row, col)`：

```cpp
if (pos[col] == row) cout << '*';
else                 cout << '.';
```

### 为什么还要记录行、斜线的占用状态？

为了避免每次放一个皇后都重新遍历之前的所有皇后，可以用三个 `bool` 数组实现 **O(1)** 冲突检查：

```cpp
bool usedRow[9] = {}; // 下标是行号，不是列号！
bool diag1[17] = {};  // \ 方向的斜线
bool diag2[17] = {};  // / 方向的斜线
```

- `true`：该行 / 斜线已被占用；
- `false`：该行 / 斜线尚未被占用。

## 四、如何给两种斜线编号？为什么数组是 17 个？

对于格子 `(row, col)`：

### 1. `\` 方向：`row - col` 相等

例如 `(1,1)`、`(2,2)`、`(3,3)` 的 `row-col` 都为 0，所以它们位于同一条 `\` 斜线上。

但 `row-col` 可能为负，因此为了避免负下标，写成：

```cpp
int d1 = row - col + 8;
```

行列取值范围均为 1～8：

```text
-7 ≤ row - col ≤ 7
 1 ≤ row - col + 8 ≤ 15
```

所以 `d1` 的取值范围是 **1～15**。

### 2. `/` 方向：`row + col` 相等

例如 `(1,4)`、`(2,3)`、`(3,2)` 的 `row+col` 都为 5，所以它们位于同一条 `/` 斜线上。

```cpp
int d2 = row + col;
```

它的范围是 **2～16**。

### 为什么 `[17]`？

C++ 数组长度为 17 时，下标是 `0～16`。因为 `diag2` **有可能访问到下标 16**，所以长度不能只开 16：

```cpp
bool diag1[17] = {};
bool diag2[17] = {};
```

| 标记数组 | 编号公式 | 实际访问的下标 | `[17]` 是否够用？ |
|---|---|---|---|
| `diag1` | `row - col + 8` | `1～15` | 够 |
| `diag2` | `row + col` | `2～16` | 够 |

这里的 **17 不是斜线数量**：8×8 棋盘每个方向只有 **15 条**斜线，只是为了方便编号，留出了不用的下标。

如果希望两个数组都只开 15 个位置，可以改成从 0 开始编号：

```cpp
bool diag1[15] = {};
bool diag2[15] = {};
int d1 = row - col + 7; // 0～14
int d2 = row + col - 2; // 0～14
```

但两组公式**不能混用**。

### 格子示意

对于第 3 行、第 4 列：

```text
row = 3, col = 4

d1 = 3 - 4 + 8 = 7
d2 = 3 + 4     = 7
```

如果另一个位置满足同样的 `d1` 或 `d2`，说明它位于当前皇后的一条斜线上，不能放置。

## 五、为什么要初始化 `= {}`？

```cpp
bool usedRow[9] = {};
bool diag1[17] = {};
bool diag2[17] = {};
```

`= {}` 表示**用空初始化列表进行初始化**。对于数组来说，每个元素会被零初始化：

- `bool` 数组：所有元素初始为 `false`；
- `int` 数组：所有元素初始为 `0`。

最初棋盘上没有任何皇后，所以所有行、斜线都必须是**未占用（false）**。

**全局数组的细节**：如果数组写在函数外面，例如 `bool usedRow[9];`，它本来就会自动零初始化，所以不写 `= {}` 也行。不过写出来更直观、统一；如果在函数内部声明普通局部数组，建议显式初始化，否则未初始化元素的值不确定。

## 六、DFS 的四个动作：判断、放置、深入、撤销

```cpp
void queen(int col) {
    // 终止：8列已全部放好
    if (col == 9) {
        printsol();
        return;
    }

    // 尝试当前列的每一行
    for (int row = 1; row <= 8; row++) {
        int d1 = row - col + 8;
        int d2 = row + col;

        // ① 如果行或斜线有冲突，这一格不能放
        if (usedRow[row] || diag1[d1] || diag2[d2]) {
            continue;
        }

        // ② 放下当前列的皇后
        pos[col] = row;
        usedRow[row] = true;
        diag1[d1] = true;
        diag2[d2] = true;

        // ③ 探索下一列
        queen(col + 1);

        // ④ 回溯：恢复本层修改的占用标记
        usedRow[row] = false;
        diag1[d1] = false;
        diag2[d2] = false;
    }
}
```

### 为什么放置前要判断，而回溯前不必再判断？

这就是本次讨论的重点。

**放置前的判断**是为了确认当前位置不和已有皇后冲突；如果冲突，`continue` 会直接跳过，后面的放置与撤销都不会执行。

一旦成功放下皇后，当前递归层就**一定**需要在尝试下一行之前撤销自己放下的标记；否则其他分支会错误地认为旧位置仍然占用。

回溯不只是“失败才退”。这道题要枚举**所有 92 种方案**：

- 后续没找到解：撤销，尝试下一行；
- 后续找到了一个或多个解：打印答案，继续探索其他分支；待后续全部搜索完成后，**仍要撤销**，尝试下一行。

只有完整地搜索完 `queen(col + 1)` 的所有分支，它才会返回当前层；执行流随之继续到撤销代码。

### 逐层恢复现场示意

```text
queen(1)
  放下第1列皇后：标记 A = true
  └── queen(2)
        放下第2列皇后：标记 B = true
        └── queen(3)
              ……继续探索，自己的临时标记也会撤销……
        撤销第2列皇后：标记 B = false
        尝试第2列的其他行……
        第2列所有分支完成后返回
  撤销第1列皇后：标记 A = false
  尝试第1列的其他行……
```

请注意：**执行 `queen(2)` 期间，第 1 列皇后仍要保留**。只有当 `queen(2)` 整体返回后，`queen(1)` 才能撤销第 1 列的占用标记。

你在对话中正确回答：当 `queen(2)` 返回 `queen(1)` 时，第二列皇后的占用标记已经恢复成 `false`。更一般的原则是：

> **谁修改状态，谁负责恢复状态；子递归返回时，子递归的临时修改应已经被撤销。**

### 为什么 `pos[col]` 不必在回溯时清零？

`pos` 只用于**打印完整方案**，不用于检查冲突；当某一列重新选定新行时，`pos[col]` 会被覆盖。只有 `col == 9` 时才打印，那时所有 8 列都有本次方案的值。

因此，必须恢复 `usedRow`、`diag1`、`diag2`；`pos[col] = 0` 可以写，但在这里**不是必需**的。

## 七、我的实际代码出了什么错？

你已经能够独立写出 DFS、终止条件、逐行枚举、两个斜线公式和回溯位置。真正的问题主要是这两处。

### 错误 1：把赋值 `=` 写成了比较 `==`

你写的放置代码：

```cpp
usedRow[row] == true;
diag1[d1] == true;
diag2[d2] == true;
```

以及撤销代码：

```cpp
usedRow[row] == false;
diag1[d1] == false;
diag2[d2] == false;
```

**问题：** `==` 只是比较，比较结果也没有被使用，并不会改变标记数组。于是所有标记一直是 `false`，程序无法识别行和斜线冲突。

**正确：**

```cpp
// 放置
usedRow[row] = true;
diag1[d1] = true;
diag2[d2] = true;

// 回溯
usedRow[row] = false;
diag1[d1] = false;
diag2[d2] = false;
```

> 调试记忆：`=` 是**赋值**；`==` 是**比较是否相等**。在 `visited` / `used` / `diag` 等标记数组中尤其要小心。若标记始终不生效，搜索可能退化为每列任选 8 行，共 `8^8 = 16,777,216` 种组合，产生巨大错误输出。

### 错误 2：忘记写 `pos[col] = row`

你定义了 `pos[9]`，并在 `printsol()` 里使用 `pos[j] == i` 判断皇后位置，但 DFS 从未把放置结果存进 `pos`。

**补上：**

```cpp
pos[col] = row; // 第 col 列的皇后放在第 row 行
```

否则程序可能即使搜索逻辑修好，也无法正确输出棋盘。

### 小错误：`usedRow` 的注释写反了

原注释是“标记已经放过皇后的行（下标：列）”。应改为：

```cpp
bool usedRow[9] = {}; // 标记已使用的行（下标：行）
```

### 本题常见的其他错误

| 错误写法或想法 | 为什么错 / 如何改 |
|---|---|
| `diag2[16]` 配合 `row+col` | 当 `(row,col)=(8,8)` 时访问下标 16，越界；应开 `[17]`，或改成 0～14 编号 |
| `pos[row] = col` | 与输出代码约定不一致；约定 `pos[col] = row` |
| `if (col == 8) printsol()` | 第 8 列此时尚未选位置；在 `col == 9` 才表示 8 列全部放完 |
| 只找到一个解就停止 | 题目要求全部 92 种合法方案 |
| 递归返回后不撤销标记 | 上一次分支会干扰后续分支 |
| 以为“找到了答案就不用回溯” | 本题要求全部解，即使找到合法棋盘也要继续探索 |

## 八、可直接提交的完整 C++ 代码（修正版）

```cpp
#include <iostream>
using namespace std;

// pos[col]：第 col 列皇后所在的行
int pos[9] = {};

// 1～8 行是否已有皇后
bool usedRow[9] = {};

// 两个方向的斜线是否已被占用
bool diag1[17] = {};
bool diag2[17] = {};

int num = 0; // 输出的方案编号

void printsol() {
    cout << ++num << '\n';

    for (int row = 1; row <= 8; row++) {
        for (int col = 1; col <= 8; col++) {
            if (pos[col] == row)
                cout << '*';
            else
                cout << '.';

            if (col < 8) cout << ' ';
        }
        cout << '\n';
    }
}

// 当前准备处理第 col 列
void queen(int col) {
    // 全部 8 列都已经放好
    if (col == 9) {
        printsol();
        return;
    }

    for (int row = 1; row <= 8; row++) {
        int d1 = row - col + 8; // \ 方向
        int d2 = row + col;     // / 方向

        // 有冲突时跳过当前位置
        if (usedRow[row] || diag1[d1] || diag2[d2]) {
            continue;
        }

        // 1. 记录、标记当前选择
        pos[col] = row;
        usedRow[row] = true;
        diag1[d1] = true;
        diag2[d2] = true;

        // 2. 处理下一列
        queen(col + 1);

        // 3. 撤销本层的标记，为尝试下一行恢复现场
        usedRow[row] = false;
        diag1[d1] = false;
        diag2[d2] = false;
    }
}

int main() {
    queen(1); // 题目没有输入
    return 0;
}
```

### 为什么输出天然按题目要求排序？

从第 1 列开始，每列的循环都按 `row = 1,2,…,8` 的升序尝试。DFS 会先完整搜索“第一列较小行号”的所有方案，再进入较大的行号；第二列、第三列……也同样如此。所以得到的 `pos[1..8]` 序列天然是**字典序升序**，不需要另行排序。

### 复杂度

- 每列尝试最多 8 个位置；在只考虑“不同行”时，搜索路径数量至多约为 `8!` 量级，斜线剪枝会进一步减少实际搜索。推广至 `N` 皇后，该直接写法可用粗略上界 **`O(N · N!)`**（每个搜索节点循环枚举至多 `N` 行）。
- 额外存储：行、斜线、位置数组和递归栈均为 **`O(N)`**。
- 对本题固定的 8 皇后，完全能够在很短时间内找到全部 **92** 种解。

## 九、与「最佳凑单」的 DFS 对比

| 比较点 | 最佳凑单 | 八皇后 |
|---|---|---|
| 每层负责什么？ | 考虑一件商品 | 给当前列放一个皇后 |
| 分支是什么？ | 买 / 不买（两个分支） | 尝试第 1～8 行（多个候选） |
| 典型参数 | `dfs(id, sum)` | `queen(col)` |
| 终止条件 | `id == n` | `col == 9` |
| 是否要恢复共享状态？ | `sum` 按值传递，不需恢复 | 标记数组是共享状态，必须恢复 |
| 题目要求 | 找最小合法价格 | 输出全部合法棋盘 |

**重要区别：** 不要把“回溯”误解成“只有失败时才撤销”。如果问题要求搜索全部方案，某个选择成功完成之后也要恢复，才能探索其他分支。

## 十、最后复习：把四个问题讲清楚

1. **为什么 `queen(9)` 就找到一个解？** 因为第 1～8 列全部放好了，每列一个且没有行和斜线冲突。
2. **为什么 `diag2[17]` 而不是 `[16]`？** 因为 `d2 = row + col` 的最大值是 16，需要下标 `16`；长度为 17 的数组才包含这个下标。
3. **为什么 `queen(col + 1)` 返回后一定撤销标记？** 因为当前列这个位置的所有后续可能已经探索完毕，接下来要尝试其他行；无论是否找到答案都要恢复现场。
4. **为什么要特别检查 `=` 和 `==`？** 因为标记数组只有真正被赋值为 `true/false`，冲突检查才会生效。

**建议的独立复写顺序：**

```text
先写 queen(col) 的终止条件
  ↓
写 for(row=1..8) 枚举候选行
  ↓
算 d1 / d2，判断能否放
  ↓
记录 pos[col]，设置三个标记 true
  ↓
递归 queen(col+1)
  ↓
把三个标记恢复 false
  ↓
最后写 printsol() 输出
```

记住这句最重要的总结：**判断能否选择 → 作出选择 → 递归搜索 → 恢复本层选择。**
